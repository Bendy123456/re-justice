# RE-Justice — 3D Training Grounds (Preview)

The CPU mode now uses an **original enclosed 3D fighting arena** created
in Blender: a large circular grassy training ground, one ancient tree
in the center, and high solid stone-slab walls around the full perimeter.

## Starting a match

Open the normal RE-Justice website, choose **1V1 VS BOT**, select one of
the characters marked READY, then press Enter/Start. When all 3D assets
are loaded, the fight launches in the new third-person arena.

The old side-view mode remains a fallback if WebGL or the optional 3D
resources cannot load. Online networking is not implemented.

## Keyboard and standard Xbox / DualSense controls

| Action | Keyboard | Controller (standard mapping) |
|---|---|---|
| Move around target | W/A/S/D | Left stick / D-pad |
| Jump | Space or H | A / Cross |
| Dash | Left Shift or P | RB / R1 |
| Light / Medium / Heavy | J / K / L | X/Y/B (Xbox), Square/Triangle/Circle (PS) |
| Block | I | LT / L2 |
| Super (4 meter bars) | O | RT / R2 |
| Throw | U | LB / L1 |
| Pause | Esc | Start / Options |
| Leave paused match | Q | Keyboard Q |

Custom rebinding for the existing named inputs (jump/power and dash/burn)
continues to work from Settings. The extra Space and Shift keys are
convenient default alternatives.

## Architecture and collision

- Blender source: `blender/build_training_arena.py`
- Edit in Blender: `assets/arena/training-ground.blend`
- Rendering asset: `assets/arena/training-ground.glb`
- Simulation and renderer: `arena3d.js`
- QA: `arena-browser-qa.mjs` and GitHub Actions workflows
- Visual-only arena model. Simple analytic floor, center-tree and radial
  wall/character colliders run at exactly 60 simulation ticks per second.
- The original 2D engine and roster frame data are kept. Existing normals
  use their original startup, active, recovery, damage and hitstun values
  adapted to 3D contact range.
- CPU, round timer, 2-round wins, block/chip damage, combo scaling and
  meter are implemented in this 3D mode. GLB bones/meshes are not involved
  in hit detection.

## Current limitations

This is the initial 3D arena-fighter prototype, not a complete Shinobi
Striker recreation. The following still need dedicated tuning:
- 3D-specific move animations, advanced air combos and true special moves
- camera behavior in unusual edge/crowding situations and mobile controls
- custom character costumes and additional animation polish
- responsive performance on older laptop GPUs; use updated Chrome/Edge
- online matchmaking/network rollback (not implemented)
- only the four roster characters with existing playable move data can fight

Collision and browser smoke tests passing does not guarantee all devices
are free of bugs. Leave the separate 2D fallback in place while testing.

## Full-body fighter animations

The arena uses the authored, frame-aware animation system in `arena-animator.js`.
This animates the original Blender-exported 65-bone male, female, and Batman rigs
without modifying frame data, hitbox timing, or Blender mesh assets.
Movement is distance-driven (feet stop when blocked against arena geometry)
with pelvis rotation, opposing rib/shoulder motion, leg recovery, foot tilt,
and breath/idle transitions. Dashes have a forward sprint lean and arm drive.
Light jabs, medium crosses, and heavy hooks have distinct windup/impact/recoil
shapes, planted legs, hip drive, rib rotation, and a guarded opposite hand.

These are runtime joint animations, not separate baked Blender Action clips.
The real-browser movement test includes visual joint regression checks and
records PNG screenshots as GitHub Actions artifacts.

## Natural walking animation pass (October 2026)

The `walk` state in `arena-animator.js` now has its own grounded procedural
cycle, separate from dash/attacks. It uses approximately 60% foot stance and
40% foot swing with smooth foot clearance, toe-off/heel-strike ankle rolls,
2-bone knee IK, a narrower foot track, subtle vertical pelvis motion,
contralateral arm swing with rearward elbow pole, and counter-rotating spine.
The input/combat speeds and animation system for dash/attacks were not changed
by this walk-only update. Tests capture heel strike, toe off and swing frames,
verify male/female elbow/knee articulation and foot-contact alternation, and
regress hand/rib clearance. Ground contact is a local gait approximation, not
full world-space foot locking; extreme movement speed or abrupt turns may still
show sliding, which should be addressed independently when refining movement.

## Stone-slab wall and grass arena update

The editable `assets/arena/training-ground.blend` and the in-game
`training-ground.glb` are generated by the actual Blender scripts:
`blender/build_training_arena.py` and `blender/arena_polish.py`.

- Seamless color-varied green lawn with an embedded PNG turf texture and
  14,500 low-poly short-grass tufts; no brown checkerboard earth tiles
- Three staggered courses of **20 enormous medium-gray stone slabs per row**
  on both the inside and outside of the arena wall, with thin joints and
  correctly oriented slab faces; all stones use nearly identical cool-neutral
  gray materials in a clean modern superhero-training-ground style
- Individual medium-gray top capstones; no little bricks, warm sandstone
  patches, or decorative buttresses
- The central natural tree, arena radius (34m), wall height (12.5m), tree
  collider, wall collider, controls, fighters, and combat remain unchanged
- A workflow regenerates, visually previews, validates, and commits the
  actual Blender source file, playable GLB and review files to main

Grass tufts and slabs are visual meshes only. The deterministic ground and
wall collision rules continue to use the same analytic surfaces and radii.
